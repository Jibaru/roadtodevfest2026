Welcome to the agentic era

  • 2023: we chatted with LLMs
  • 2024–25: LLMs got tools and started doing things
  • 2026: software is becoming teams of agents that plan, act and cooperate
  • An agent = model + instructions + tools + memory, in a loop

Why Go for agents?

  • Agents are concurrent by nature — goroutines and channels are the native fit
  • One static binary: the whole show tonight ships as a single file
  • Typed tools: the function signature IS the contract the model sees
  • Boring, fast, deployable — perfect for agents that must not fall over

Don't take my word for it — you'll see each claim in the app's real code.

route One round, end to end

1Your phone sends submit_repo over WebSocket

3One tarball download → in-memory snapshot (capped, filtered)

6Findings come back as JSON → ranked by severity
7You vote the most valuable finding — reviewers score points
8The Lead Reviewer closes with a verdict. Next repo!

One HTTP button on the stage drives all of it — the state machine does the rest.

The agents are non-deterministic — the show can't be. Every transition is guarded in the domain; one mutex owns the truth. Deterministic orchestration around stochastic agents.

[ why Go — proof 1/4 ]

Three reviewers digging at once = three goroutines

var wg sync.WaitGroup
for _, reviewer := range []Reviewer{Bugs, Security, Simplify} {
    wg.Add(1)
    go func(r Reviewer) {
        defer wg.Done()
        findings, err := crew.Review(ctx, r, snapshot, onStatus)
        ...
    }(reviewer)
}
wg.Wait()

This is the real code from the show you just watched. No async/await, no thread pools, no callback pyramids — the language primitive IS the feature.

[ why Go — proof 2/4 ]

Broadcasting to every browser = one channel each

for client := range hub.clients {
    select {
    case client.send <- data:   // mailbox: a buffered channel
    default:                    // slow client? drop it,
        go client.close()       // never stall the show
    }
}

Hundreds of viewers, one 512 MB instance. Backpressure handling is a select statement — in most stacks this is a message broker.

[ why Go — proof 3/4 ]

A live show can't crash — errors are just values

findings, err := crew.Review(ctx, reviewer, snapshot, onStatus)
if err != nil || len(findings) == 0 {
    // plan B: the failure itself becomes a visible finding
    findings = []Finding{{
        Severity: "low",
        Title:    "Reviewer went offline",
    }}
}

Gemini down? The failure ships as a finding. Repo unfetchable? The verdict says so and the show moves on. Every fallback is a visible `if err != nil` — no hidden exception paths on stage.

[ why Go — proof 4/4 ]

An agent that never answers can't freeze the show

ctx, cancel := context.WithTimeout(ctx, 45*time.Second)
defer cancel()

findings, err := crew.Review(ctx, reviewer, snapshot, onStatus)

// every external call in the show has a budget:
// repo fetch 45s · review 3m · verdict 30s — then the fallbacks kick in

Cancellation flows through every layer — ADK, HTTP, the tarball download — because context is the standard library's contract, not a bolt-on. LLMs are the slowest, flakiest dependency you'll ever call; deadlines are not optional.

Not one of these needed a framework. Agentic workloads are concurrent, failure-prone, I/O-bound systems programming — exactly what Go was built for.

The agents chose what to read

  • read_file is a plain typed Go function — the structs ARE the schema the model sees
  • Each reviewer decided which files mattered for its specialty — you watched it choose
  • Tool calls are budgeted: 12 reads max, then it must conclude
  • Your vote on the findings is the human-in-the-loop
