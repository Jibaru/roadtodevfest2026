Welcome to the agentic era

  • 2023: we chatted with LLMs
  • 2024–25: LLMs got tools and started doing things
  • 2026: software is becoming teams of agents that plan, act and cooperate
  • An agent = model + instructions + tools + memory, in a loop

Why Go for agents?

  • Agents are concurrent by nature — goroutines and channels are the native fit
  • One static binary: the whole show tonight ships as a single file
  • Typed contracts: the struct IS the schema the model must fill
  • Boring, fast, deployable — perfect for agents that must not fall over

Don't take my word for it — you'll see each claim in the app's real code.

What you just experienced

Every submission, agent call and progress update flowed through goroutines and channels.

route One video, end to end

1You paste a link → POST /api/videos returns instantly, job hits the channel
2A free worker picks it up — while other workers chew other videos
3yt-dlp fetches metadata + subtitles in two phases (manual first, auto fallback)
4The Language Detective agent reads title + description — covers and dubs included
5VTT parsed, rolling cues collapsed, noise dropped
6The Romanizer agent turns ja/ko into romaji; the Translator renders every line in Spanish
7Word-level timing by syllable weight → Postgres → ready
8Every stage streamed live to every browser over one WebSocket

And while this video moves through its stages, three more are doing the same on other workers.

replay a failed video goes back to the queue on resubmit — YouTube's bot checks are intermittent

The agents are non-deterministic — the pipeline can't be. Every stage has a timeout and a fallback, and each one broadcasts its progress so the audience sees the pool working. Deterministic orchestration around stochastic agents.

Swapping storage is one constructor line. The agents are behind interfaces too — the show ran offline in rehearsal.

type Agents interface {
    DetectLanguage(ctx, title, description) (string, error)
    Romanize(ctx, language, lines) ([]string, error)
    Translate(ctx, sourceLang, lines) ([]string, error)
}

// wiring in main.go — one flag swaps the whole cast:
if cfg.FakeAgents {
    crew, fetcher = &fake.Crew{}, fake.Fetcher{} // offline, zero tokens
} else {
    crew, _ = agents.NewCrew(ctx, apiKey)        // the real Gemini crew
}

Small implicit interfaces make Gemini and yt-dlp swappable like a database. Every rehearsal of this talk ran the full pipeline offline — the workers never knew.

[ why Go — proof 1/4 ]

N videos processing at once = N goroutines and one channel

var wg sync.WaitGroup
// the entire worker pool:
for i := 0; i < workers; i++ {
    go s.worker(i)
}

func (s *Service) worker(n int) {
    for job := range s.jobs {
        s.process(job)   // yt-dlp + three agents + Postgres
    }
}

This is the entire worker pool from the app you just used. No job framework, no Celery, no Sidekiq — a channel and a for loop ARE the queue.

[ why Go — proof 2/4 ]

Progress to every browser = one channel each

for client := range hub.clients {
    select {
    case client.send <- data:   // mailbox: a buffered channel
    default:                    // slow client? drop it,
        go client.close()       // never stall the show
    }
}

Every stage of every video streams to every browser. Backpressure handling is a select statement — in most stacks this is a message broker.

[ why Go — proof 3/4 ]

A live pipeline can't crash — errors are just values

displays, err := agents.Romanize(ctx, lang, texts)
if err != nil {
    // plan B: original script — degraded but singable
    displays = nil
}
translations, err := agents.Translate(ctx, lang, texts)
if err != nil {
    // plan C: no translation line — the karaoke still ships
    translations = nil
}

Romanizer down? Ship the original script. YouTube bot-checks the IP? The card shows why and a resubmit retries it. Every fallback is a visible `if err != nil` — no hidden exception paths on stage.

[ why Go — proof 4/4 ]

An agent that never answers can't freeze the show

ctx, cancel := context.WithTimeout(ctx, 45*time.Second)
defer cancel()

res, err := fetcher.Fetch(ctx, youtubeID, detectLang)

// every external call in the pipeline has a budget:
// yt-dlp 2m · each agent 2m — then the fallbacks kick in

Cancellation flows through every layer — ADK, the yt-dlp subprocess, Postgres — because context is the standard library's contract, not a bolt-on. yt-dlp and LLMs are the slowest, flakiest dependencies you'll ever call; deadlines are not optional.

checklist Go for agentic development — the scorecard

boltMany videos processing at oncegoroutines
cell_towerLive progress to every browserchannels + select
errorLLMs fail, constantlyerrors are values
handshakeAgent I/O needs contractstyped batches, parsed strictly
timerSlow or hung model callscontext deadlines
rocket_launchShip the demo anywhereone static binary

Not one of these needed a framework. Agentic workloads are concurrent, failure-prone, I/O-bound systems programming — exactly what Go was built for.

What building this taught me

  • Treat YouTube as a hostile dependency: retries, cookies escape hatch, full offline mode
  • Agents are just another dependency — put them behind an interface (rehearsals ran offline)
  • An agent can BE the library your language is missing
  • The demo people remember is the one they were part of — bring your own song
